# Personal radio experience

Current product contract, 16 October 2026. This document and `REQUIREMENTS.md` replace earlier descriptions of a station placeholder, manual-only DJ tests, and a planned-only news runner. Implementation details and future extensions belong in `LISTENING_ROOM_WORKFLOW.md`.

## Who this is for

A listener has music in Jellyfin and wants to press Play, then hear occasional short news updates in a host's voice. They should not need to understand model prompts, request ledgers, or background jobs. A more involved listener can choose sources, interests, delivery, and schedules without operating a live broadcast desk.

The current radio uses the music queue the listener chooses. Mood describes the host's delivery. It does not analyze audio or choose music. News is prepared as complete recordings before playback.

## Entry and first use

1. Connect to Jellyfin and select music libraries. If discovery is loading, empty or failed, Use another account or server opens sign-in with the server retained and credentials cleared. Back keeps the existing account and library choices and restores focus. A failed replacement sign-in does not disconnect the current account. A failure to save the replacement likewise keeps the latest committed account. The current account remains active while the replacement is being saved. Confirming Sign out cancels a replacement that has not committed, including when sign-out later fails. An account already committed before that confirmation is the account being signed out. Signing into a second installation must not expire the first installation’s session. A successful one refreshes selection, including for the same account. Open All songs with ordinary music controls. Missing AI keys never block music.
2. Open DJ in the persistent player. Explain DJ breaks separately from news preparation. With no profile selected, offer the News bucket destination for setup.
3. News bucket → Settings offers one profile setup form: choose sources, a saved DJ, optional interests, and mood. Source/DJ management and provider keys open shared Settings with a return action; preserve the draft.
4. Start with the existing default profile. Additional named profiles are optional. A copied profile starts unavailable, with automatic preparation off and no copied run history or counters. Copy the current draft without saving it back to the original profile or changing playback. Choose the copy from Setup profile, use Review room options to make it available, then separately enable preparation if wanted. Switching with unsaved changes offers Save and switch, Discard and switch, or Cancel.
5. Review preparation cadence, selection, maximum recordings, provider requirements, and cost explanation before saving an enabled workflow. Saving setup alone does not authorize new paid work. Enabling preparation does.
6. To hear saved news automatically, choose that profile in the player and separately enable DJ breaks. The edited profile and playback profile may differ; identify both by name. The player distinguishes an unselected profile from no available profiles. Incomplete available profiles remain selectable so their missing DJ, news sources, or mood can be explained before enabling breaks. Enable stays unavailable until those saved requirements are complete; Disable remains available whenever breaks are on. Offer the existing News bucket destination and spell out Settings and, when needed, the named Setup profile choice. Preserve the current editing profile, tab, and draft. Saved playback does not require provider keys, automatic preparation, or an already-ready recording; an empty pool keeps music playing.

Preparation can be enabled only after selected sources, a saved host with voice settings, mood, and configured OpenAI/ElevenLabs keys are available. An X token is required only for selected X sources. Show each missing item beside a direct setup action. With no saved DJs, identify that a first DJ is needed and open shared DJ management. With saved DJs but none selected, focus the DJ selector. Returning from management retains the setup draft and restores focus to Manage DJs. Check current prerequisites again when saving. Saving incomplete setup is allowed with preparation off. Turning preparation off remains available even if credentials or sources disappear.

Setup is a short form rather than a forced wizard. Sources, host, mood, interests, and preparation preferences share one explicit save. Unsaved edits remain drafts through music navigation and shared-management visits. A visible unsaved state distinguishes the draft preparation switch from the saved running state. Profile switching offers Save and switch, Discard and switch, or Cancel for the entire draft. Existing recordings remain reachable with incomplete setup or missing keys. Advanced manual tools stay collapsed. Neutral voice samples help choose a voice in the editor. Saved DJs separately offer an optional delivery preview: explicitly generate once, replay locally, and show Outdated after a saved voice or delivery change. Regeneration is explicit and a failed attempt keeps the prior recording. Neither preview enables preparation or DJ playback. The DJ editor configures the host’s voice and delivery. Set listening cadence in Settings → General → DJ playback. The listener chooses the music queue.

An offline catalog request keeps the existing connection and offers Try again. An expired Jellyfin session opens sign-in with the server and username filled and the password empty. Within the running app, signing back into the same server and account retains unsaved radio setup, edited script and manual preparation state through library selection. It neither saves these edits nor repeats preparation. A different account, different server or explicit sign-out clears these unsaved drafts. Drafts do not survive quitting the app. Reauthentication restores the saved music session paused. If this Mac cannot retain its local connection identity, music remains available for this session and Settings explains that sign-in may be needed after quitting. A newly accepted session in this mode removes any older restorable account before success.

Explicit Sign out is also a stop boundary for paid preparation. The confirmation explains that unsaved news setup and script edits are discarded, saved profiles/DJs/keys/recordings stay on this Mac, automatic preparation pauses across profiles, and in-progress text/voice generation is canceled. Already dispatched requests can still finish or incur a charge; completed recordings are preserved. Keep saved preparation opt-ins, settings, counters and history, but require an explicit Resume in News bucket → Settings after signing in. Reopening signed out must not start preparation. Confirming sign-out immediately supersedes older pending sign-ins, including while the preparation pause is being saved. A failed pause save leaves the account connected. If sign-out fails, the previously committed account stays connected and those older sign-ins remain superseded. If removing the saved connection fails, keep the account connected, retain the preparation pause and report that sign-out did not finish with Retry. Expired Jellyfin authentication uses the reconnect flow above and does not trigger this explicit-sign-out pause.


## Everyday listening

The listener chooses songs, an album, a playlist, or a queue and presses Play. Browsing and setup do not interrupt music. Reopening restores the prior listening context paused. News controls are optional and reachable from every library page.

Two independent choices govern radio behavior:

| Choice | Default | Effect | Does not imply |
| --- | --- | --- | --- |
| Automatically prepare news | Off | Check selected sources while the app process runs and Mac is awake; assess new articles; save qualifying script and voice audio | Playback, music selection, or running while the app has quit |
| DJ breaks | Off | Use saved matching fresh recordings at suitable song endings | Provider requests, enabling preparation, or speaking immediately |

Preparation defaults to every three hours, major developments only, maximum three automatic recordings per local day. Daily scheduled checks are also bounded by cadence. Text assessment can cost money without producing a recording. Limits apply to scheduled preparation for each profile, not an account-wide currency budget. Manual text/audio preparation and voice-preview generation are explicit additional provider actions outside those limits. Disclose that scope beside their controls; replaying cached audio makes no provider request. No source article is promised to be discovered.

Enabling or resuming preparation must use confirmed saved keys. If a required key was removed first, activation fails without changing the saved profile. If a key edit is requested during an enabled setup save, it waits until that save finishes. A later removal retains the saved preparation choice and setup explains what needs repair. Incomplete setup and OFF saves remain available without keys and do not wait for a pending key edit. X credentials are required only for selected X sources.

DJ breaks default to every three songs, counting natural completions rather than manual skips. A saved take may wait for a suitable ending. An empty ready list leaves music playing. Repeated interruptions and late endings must not replay old news or cause duplicate queue advances. Article identity ignores verified tracking fields while keeping original source links. A tracked and plain link to the same supported article must not cause another review or replay, including after restart. Semantic query fields remain part of the identity; saved review outcomes remain intact.

Music pause pauses speech and transition timing. Music pause does not pause the independent preparation workflow. Disabling DJ breaks stops its pending/active speech and keeps music available. Turn off automatic preparation is available during a running check. It immediately saves OFF for the named profile, prevents future checks, and requests cancellation without saving other setup edits. A failed stop remains visible after navigation and can be retried. A provider request already dispatched may have been charged. Saved results remain available.

A missing, empty, or incomplete audio file leaves its saved script, settings, and selected ID intact. Listen, use, and schedule are unavailable for that file. Explain how to load its script for an explicit replacement; never regenerate automatically. The normal Generate audio take action reuses a valid matching recording, including a later replacement. Generate another take explicitly requests a new variation. Saved details show the original news interests and label missing publication dates.

Audition Pause keeps the recording and current position even when pressed during playback startup. Resume continues that recording; rapid pause/resume must not reset it or show a false error. Stop, leaving Saved audio, or starting music ends the audition. A genuine playback failure remains visible and allows an explicit new attempt.

Seeking preserves a scheduled/active DJ break by default, following the global Keep the DJ when seeking setting. Seeking to the exact song endpoint follows repeat and queue order without counting a natural completion or advancing DJ cadence. Playback keeps its playing or paused intent. A retained break finishes before continuation; a paused break waits for Play. Seeking back into the song makes the retained break wait for its ending again. If the DJ has started speaking, pause the same clip at its current position, restore the music level, and resume only its remaining speech at the next suitable ending. Play after a paused rewind resumes music first. Already-finished speech is never replayed. The player explains when speech is waiting for the song ending. A seek short of the endpoint may still count when the remaining audio ends naturally. Explicit track replacement cancels its placement; an unheard automatic recording may wait for another ending. Transition settings control talkover or between-song delivery without regenerating voice audio. Preview transition in app Settings compares draft timings with sample music and a bundled saved voice. It needs no queue, key or provider request. The demo pauses music and leaves it paused when stopped or finished. Later music transport commands stop it, including paused song changes and seeks; volume, shuffle and repeat do not. Changing a draft timing/style or leaving General settings stops the demo without saving or starting it again. Canceled attempts cannot change a replacement preview or display stale errors.

## What the listener can see

The player popover shows playback state, selected playback profile, host, next song condition, upcoming/current script and source links, and last heard this session. A separate preparation line names the profile it describes and links to its setup. It must never describe the page's profile as the playback profile.

News bucket shows the profile being inspected, preparation status, timestamp and reason for its last check, actual next check, daily check/recording usage, and fresh matching recordings ready to play. Count labels define their scope. Review history is global and says so. It is not a count of all news on the internet or money spent.

Automatic preparation and manual activity have separate status. If activity or saved news cannot be checked, retain the draft, lock setup/profile changes and offer Retry. Independently confirmed automatic settings and scheduled counters remain useful; cached recordings say last loaded. If automatic status itself cannot be refreshed, show only the last saved automatic setting, with no current-looking counters or last-run claim. The player’s automatic preparation line follows the same saved-status rule. A successful status retry restores editing without saving the draft or starting generation.

Use these states in ordinary language:

| State | What the user sees or can do |
| --- | --- |
| Partial source coverage | Keep usable stories and show the saved named source warning beside ready, draft and scheduled/current stories, and in the player’s DJ story view. Label missing or invalid reference dates Date unavailable, including in article history. If source reads fail or return unreadable data and no fresh story can be assessed, report incomplete coverage as a failure and require Resume. If readable stories were assessed but none was selected while coverage was incomplete, record Incomplete source coverage, keep preparation enabled and wait for the next scheduled check. Make no recording and do not retry immediately. Complete readable coverage with no qualifying story remains a no-news result. For Hacker News, a missing or mismatched story identity, unreadable recent story or unsafe supplied link counts as incomplete coverage. Deleted, dead, known non-story and validly dated old/future items are normal exclusions. A story without a URL may use its verified discussion link. For X searches, accept an explicit empty post list or an omitted list with a zero result count as empty. Unreadable post data, malformed error results and contradictory supplied counts require a coverage warning; usable posts remain available. Undated entries are skipped in automatic checks with an explanation. |
| Setup incomplete | Identify missing sources, host, mood, or provider keys and offer the relevant setup action |
| Off | Preparation is off; saved audio is available |
| Checking | A persisted check is in progress; do not claim audio is ready |
| Recording saved | Show finish time; it becomes eligible only if it matches current setup and freshness rules |
| No qualifying story | Show actual reason; no speech is generated; music continues |
| Incomplete source coverage after assessment | Name the unreadable sources, say no story was selected from the readable sources and show the next scheduled check; preparation stays on, no recording is made and no immediate paid retry occurs |
| Daily limit | Say which daily count reached its cap and when checks can resume; this is not an error |
| Paused after failure | Show saved error and Resume preparation; missing or rejected keys direct Settings → Provider keys, independently of saved DJ playback; avoid automatic paid retries |
| Interrupted | Explain that completion is uncertain; reconcile saved artifacts and require explicit resume if unresolved |
| Room unavailable | Explain that preparation and automatic playback require an available room |
| Status refresh failed | Keep last-known data with an unavailable/stale notice and Retry; do not report a false Off state |

A due timestamp is a target, not a promise. A running manual operation can delay preparation. Sleep or quit prevents execution. On return, coalesce missed slots into one current check. Do not read yesterday's backlog as today's news.

## Done criteria and evidence

Use the [observable acceptance checklist](ACCEPTANCE_CHECKLIST.md) to trace each STAR result to concrete checks. Every linked result remains required; a grouped fixture or passing build cannot substitute for the complete story.

Disabled controls and pending forms keep readable labels and values; a disabled primary action uses a neutral surface rather than faded text. Active transition-stage timings remain readable.

A feature is complete when its current contract is consistent across PRD, service behavior, and UI; affected scenarios pass focused end-to-end or manual checks; and failures/limits can be understood from visible text without opening implementation files. Review actual artifacts, not only proposals. Reopen a decision when a failing scenario exposes a gap.

Engineering verification uses local Electron or an isolated renderer/service fixture with real storage paths and substituted providers. Fixture results do not establish source coverage, actual provider delivery, or subjective voice/transition quality. Record exact checks and remaining limitations in `IMPLEMENTATION.md` and the requirement-by-requirement [acceptance audit](UX_ACCEPTANCE.md). Do not claim the 90% acceptance milestone until the denominator and current evidence are recorded there. Do not equate internal review with regular-user validation or call the UX perfect without evidence from listeners.

Weather, calendar/reminders, budget pricing estimates, AI song selection, external station broadcasting, and release packaging are outside this contract. They should not appear as working controls.

Shared source deletion names every setup profile using that source before confirmation. If the selected playback profile loses its last source, confirmation explains that DJ breaks will turn off and points to News bucket to choose another source. Cancel preserves the source; confirmed deletion removes its references from those profiles. Saved recordings keep their original source provenance. Saving sources never prepares a story by itself.

Shared DJ deletion likewise names every profile using that host before confirmation. Those profiles need a replacement for future preparation. When enabled DJ playback uses an affected profile, the confirmation also says its breaks will turn off and directs the listener to choose another DJ before explicitly enabling them again. Do not warn that unrelated or already-disabled playback will turn off. Cancel keeps the host and choices; saved scripts and recordings retain their original DJ information. Wrap long profile names so the confirmation and actions remain usable when text is enlarged. Keep long confirmation titles compact and repeat the complete DJ or source name in wrapping body text. The listener can read the distinguishing end of a name before deleting; Close, Cancel and Delete remain reachable with the keyboard at 200% app zoom. The accessible dialog name retains its complete title.

Automatic song and DJ-break continuation retains existing playback intent. After an ended-song DJ break completes, fails or is stopped, music follows its repeat mode: repeat-one restarts that occurrence; other modes advance or end the queue normally. Stopping a paused break keeps this continuation paused. Manual Next still skips even while speech follows an ended song. Seeking a converted stream while paused keeps it paused and prepares the requested offset.


At narrow effective widths, the player uses two rows to keep volume, seeking, transport, DJ and queue controls usable. In short windows, the sidebar scrolls without collapsing navigation under Settings. A compact queue or song-details drawer temporarily replaces the main content area above the player. Covered page controls and notices leave keyboard navigation until the drawer closes; closing restores them and returns focus to its opener. The sidebar and player remain available. Enlarging the app does not authorize preparation or change the music session.

Album search finds titles and album artists within the chosen music libraries. An album matching both appears once; later pages preserve the same combined order. This is part of the ordinary music-browsing flow in M5.
