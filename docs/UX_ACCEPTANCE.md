## Evidence rules and target

The denominator is the full set of current requirements in `REQUIREMENTS.md`, including its music, playlist, persistence, accessibility, security, and voice-preview requirements, plus R1–R12 in `RADIO_EXPERIENCE.md`. M1–M15 there clarify the existing music requirements without replacing them. Future features remain separate as defined there; existing requirements cannot be removed to improve the score.

For the requested 90% target, report two separate results:

- Engineering acceptance coverage: verified observable acceptance checks divided by all current checks in this audit. Source inspection alone establishes implementation, not a passed interaction check. A missing or contradicted result is not a pass.
- Usability: completion without help, error recovery, perceived clarity, and audible quality require observed listener sessions. Do not infer a usability percentage from internal code review or fixture checks.

Every critical invariant must pass regardless of percentage: no lost edits, no unrequested paid work, no credential exposure, no silent overwrite of a selected recording, no automatic retry of uncertain paid work, no duplicate advancement/replayed speech, and working keyboard access to essential controls. Completion requires all current requirements to be implemented and verified; 90% is a progress milestone, not permission to leave a critical flaw.

## Human Interface Guidelines applied

Apple's [onboarding guidance](https://developer.apple.com/design/human-interface-guidelines/onboarding) supports learning through use, optional brief setup, and help beside the relevant control. Apple's [Settings guidance](https://developer.apple.com/design/human-interface-guidelines/settings) supports familiar defaults and keeping configuration focused on choices people need. The implementation implications here are optional radio setup, contextual missing-prerequisite actions, preserved edits when visiting shared management, and explicit feedback after save. These are design choices informed by the guidance, not certification of Apple compliance or proof of user satisfaction.
