## Evidence that remains separate

No indexed record establishes a live text/voice generation session, paid billing, an audible-quality session or observed uncoached listener usability. Muted playback can establish decoding, time advancement and technical transitions. It cannot establish acceptable mixing, pronunciation or perceived interruption. Saved/bundled MP3 audio is not evidence that a provider produced the expected delivery.

Actual safeStorage and isolated Keychain checks establish their named OS storage operations. Injected unavailable-store results do not prove a real OS outage. Registered MediaSession callbacks do not establish physical media keys. Date adapters and explicit scheduler ticks do not establish sleep/wake behavior. Chromium accessibility names and keyboard checks do not establish a full VoiceOver session. Synthetic window blur does not prove OS app switching.

Native webContents screenshots show app content. They do not establish desktop wallpaper/menu/Dock context or OS display-scale legibility. The incomplete desktop capture stays incomplete.

## Reading dated evidence

Each original record retains its source hashes, failures, fixture corrections, limitations and historical dispositions. A matching filename, green result or later audit does not refresh its source snapshot. Current dispositions live in the [acceptance inventory](ACCEPTANCE_CHECKLIST.md). Source changes require a scoped freshness review before using older evidence for a current claim.

For example, the earlier live-player record established a universal endpoint response and decoded playback. The later duration investigation found that advertising MP3 direct play could return a full file despite the requested offset. PR58 corrected that route and recorded new byte/duration and native evidence. Earlier route success must not be read as proof of the corrected offset behavior.

Historical sub1280×720 and enlarged-zoom observations stay available but are deferred by Anton. This audit runs none of them.

## Maintaining the distinction

New verification records must state the actual application/runtime, data and provider substitutions, live origins if any, fault/timing adapters, inspected outputs and remaining limits. Keep live and controlled subcases identifiable inside mixed records. Record source/artifact hashes without rewriting an old record after a new build. Link each record from its affected acceptance discussion.

Use source/artifact inspection, native interaction, service/storage integration, live upstream, OS/hardware and observed listener/audible proof only for what each establishes. A partial result remains partial even when its narrower checks pass. Count a requirement only after every proof kind and variant it names is covered.
